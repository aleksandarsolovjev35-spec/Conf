# Публикация на GitHub Pages

Сайт статический, сборка не нужна: Pages отдаёт содержимое ветки `main`
как есть.

- Адрес: <https://aleksandarsolovjev35-spec.github.io/Conf/>
- Источник: ветка `main`, папка `/`
- Файл `.nojekyll` отключает обработку Jekyll — нужно, чтобы Pages не пытался
  интерпретировать содержимое как тему и отдавал файлы один в один.

## Обновление

Pages пересобирается при каждом пуше в `main`, то есть после мерджа PR.
Ручной запуск сборки через API требует прав `pages:write`; если их нет,
новый коммит в `main` — единственный способ пересобрать.

Проверить, на каком коммите сейчас опубликован сайт:

```sh
gh api repos/aleksandarsolovjev35-spec/Conf/pages/builds/latest \
    -q '"status=\(.status) commit=\(.commit) created=\(.created_at)"'
```

Сравнить с текущим `main`:

```sh
git fetch origin main && git rev-parse origin/main
```

Если коммиты отличаются — в `main` уехал мердж, после которого сборка
не запустилась. Лечится новым коммитом в `main`.

## Кэш

GitHub Pages отдаёт HTML через CDN с кэшем около 10 минут, а служебные
заголовки кэширования для статики задать нельзя. После обновления сайта
страницу смотрят с жёстким обновлением: `Ctrl+Shift+R` (Windows/Linux) или
`Cmd+Shift+R` (macOS), либо в приватном окне.

## Локальная проверка

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

Открыть <http://localhost:8000/>. Сервер нужен только для просмотра,
публикация идёт напрямую из репозитория.
